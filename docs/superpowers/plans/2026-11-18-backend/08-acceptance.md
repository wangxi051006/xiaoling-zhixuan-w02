# P08 · 功能验收、安全审计与上线门禁

**状态：待执行，无通过声明。** [总计划](./00-master.md) · [机器契约](./10-contracts.md) · [部署运行](./09-deploy.md)

## 1. 独立验收流程

1. 总控在 G2 后提供固定 commit、产物摘要、迁移版本、开关配置与预发环境 ID。使用合成账号 `客户 A/B、骑手 A/B、运营、财务甲/乙、安全管理员`、测试楼栋和测试资金；不复制生产库，不向公网正式账号跑测试。金额和时间断言固定时钟；并发用屏障和真实 PostgreSQL。支付分别验 COD-only 和开启测试余额两个配置。
2. 工程师跑功能/并发自动化，总控完成三端实联调。**安全复核必须由非该模块实现者负责**；复核员按下表验证权限、资金、外部暴露、审计与恢复，不以扫描通过代替人工复核。运营验实际备货/拒付/退回，财务验收应收、实收、上缴差额、退款和余额导入口径。
3. 在 `docs/evidence/launch/` 保存脱敏索引，不放原始用户/资金/OTP/签名和密钥：`用例 ID / 版本 / 配置 / 命令或操作 / 预期 / 实际 / 证据位置 / 负责人 / PASS|FAIL|NOT RUN`。敏感证据存受限系统。修复后重跑受影响用例和相关共用事务，未运行的阻断用例不能签发。

## 2. 功能与一致性矩阵

| ID | 场景 | 通过标准 |
| --- | --- | --- |
| TRADE-01 | 三件装与单件争抢最后物理库存；下架后用旧报价提交 | 仅库存允许的事务成功；无超卖；下架/变价返回对应冲突，原有单正常履约。 |
| TRADE-02 | 重放创建；同键异参；提交成功但客户端超时 | 同参一个订单；异参拒绝；查询可找回既有单、不双扣与不额外占位。 |
| TRADE-03 | 写收款/事件前故障注入；取货与取消并发；已分拣取消 | 错误全回滚；取货/取消恰有一个成立；待归架不回可售，返库或损耗流水只处理一次。 |
| TRADE-04 | 本人预约截止自助取消、即时未分拣取消、越界取消 | 只有合法订单可由用户取消；资金/时段/库存按规则一次性变更。 |
| SLOT-01 | 固定时钟营业跨日、窗口边界、无可用窗口、运营调整上限 | 上海日期正确；到 `dispatch_at` 不接预约，窗口结束不接单；禁止容量低于占用和随意改窗。 |
| SLOT-02 | 容量 1，预约和即时并发抢占；取消释放后再占 | 同池最多一单；合法取消只释放一次；分拣后/到期/送达不重复释放。 |
| SLOT-03 | 重启/任务租约失效，重复执行到期预约；延迟到窗后 | 初始预约只在到时进入备货一次；备妥才可放单；逾期告警、不擅自换窗或完成。 |
| PAY-01 | COD-only：即时与预约各跑一单；收款/送达重放；拒付/少付 | 下单不显示已收；全额现金确认才能送达，同事务仅一条收款/收入；拒付进入退回，无默认收入，验收后回可售。 |
| PAY-02 | 收款汇总、重复批次、同人复点、少缴、线下退款 | 一收款一批次；不同财务账号复点；差额可追溯；COD 已收款退款须另存实际退款凭据，审批不等于退款到账。 |
| PAY-03 | 测试余额不足、并发双扣、重复退款、取货后未送达退回、改开关退历史款 | 余额不负、同笔扣/退唯一；未送达退回验收与退原钱包同事务；余额不足不自动改 COD；关开关不挡历史退回。 |
| PAY-04 | 余额导入干跑、重复批准编号或业务参考、总额校验、初始账本 | 未审批不导入，干跑无写入，导入单次、期初加流水等于期末；实际来源由运营/财务单独批准。 |
| PAY-05 | 微信 UI、直接报价/下单尝试、路由清单 | 显示待接入且禁用；直接请求 `PAYMENT_METHOD_DISABLED`；不存在第三方微信支付与回调路由。 |
| RIDER-01 | 同单双抢、同骑手双活跃、回收与取货并发 | 冲突方 409，唯一约束成立；非当前骑手不能取送；下线不接新单。 |
| RIDER-02 | 大厅、历史、催单和本人报酬 | 不公开完整地址/电话；催单限频且只发给正确对象；收入取实际送达的唯一流水。 |
| UI-01 | 桌面与 390px 三端真实 API；完整 COD 单与预约余额取消 | 保留手账风格、无角色切换/假数据；状态与返回一致；刷新和错误可恢复。 |
| UI-02 | 无网络、超时、时段满、调价、余额不足、抢单失败 | 有明确可恢复反馈；无假成功；不得自动换时段、支付或覆盖新状态。 |

## 3. 安全审计与恢复矩阵

应先评审数据分类、权限和信任边界，再做合并检查、预发复核、签发和线上回查。采用 ASVS L2 适用条目映射；留不适用理由和审核人。以下均为内部防御验收，不在未授权环境测试。

| ID | 审计方式 | 阻断条件 |
| --- | --- | --- |
| SEC-01 | 自动化角色×站点×对象矩阵；独立客户、骑手、运营、财务会话，检查账号停用 | 跨账号/骑手/角色/站点读写、自己审批、普通管理员可改余额、停用仍可使用。 |
| SEC-02 | 检查 OTP、OIDC/MFA、Cookie、CSRF、入口隔离和限频 | 可重用验证码、可绕过员工 MFA、无有效来源/CSRF 校验、会话跨域或可冒用。 |
| SEC-03 | 确认大厅/历史/API 字段白名单、审计副本、日志与环境隔离；输入限制和预发 CSP | 敏感信息外泄；公共日志留完整电话/地址或认证材料；能改删审计证据。 |
| SEC-04 | 代码与依赖复核、secret/SBOM、`govulncheck`、前端依赖检查、镜像/制品扫描；建立责任人与复测 | 严重/高危未关闭；支付、权限、迁移、发布变更没有复核；构建产物含生产凭据或测试登录。 |
| OPS-01 | 检查 TLS、入口策略、网络 ACL、生产 OTP/IdP、防止 Go/PG/诊断公用；故障告警实际到人 | 公网可直接访问管理、数据库、诊断或 Go；伪造身份/短信可在生产启用；告警无人接收。 |
| OPS-02 | 根据固定版本实际升级/应用回滚、停止新单/放单并继续存量操作 | 回滚不可用、旧版读不了前向兼容数据、存量收款/退款无法继续。 |
| OPS-03 | 将脱敏生产等价库 PITR 恢复到隔离环境，计时并核对库存、窗口、COD 和余额；演练新主机配置恢复 | 恢复失败、对不上账或超过经批准的 RPO/RTO（默认 ≤ 15 分钟、≤ 2 小时）。 |
| OPS-04 | 15 分钟实际负载：50 并发用户、20 骑手 10 秒轮询；报告工作负载、种子规模及 P95 | 默认查询 P95 > 200ms、下单事务 P95 > 500ms、5xx ≥ 0.5%，或任何交易不变量被破坏。 |

## 4. 放行与签字

- **COD 放行**：共享、安全和运维门禁全过；COD 用例和模拟线下流程通过；运营批准收现金、拒付/退回值班、财务上缴与实物差异处理。测试余额开关关；试点发布后实际核查日对账，到人告警，不能以真金白银做未经批准的测试。
- **余额独立放行**：以上共有门禁及 PAY-03/04 全过；财务/运营确认余额真实来源、使用条款与适用义务、初始余额导入是否有授权、退款与对账责任；不得因 COD 已投产而自动打开余额。首发仅 COD 时，余额实账签发记录为 `NO-GO（保持关闭）`，测试环境仍检查账本正确性。
- **共用阻断**：严重/高危未修复、越权、数据泄露、资金/库存/窗口不变量失败、回滚/恢复失败、未执行阻断项。其他发现需记录措施、负责人及截止日期，并经安全复核和发布负责人接受。每张签发单包含版本、渠道及开关、证据索引、运营/财务/安全/发布四方签字及签发时间。签字前不切公网，发布后验证三端与受控入口，并检查首个运营日闭环。
