## 执行步骤

- [ ] 用真实 PG 写报价失败/伪造价格/跨人报价/同幂等键异参/无余额/最后容量或库存冲突的测试。在 `quote.go`、`order.go` 绑定规范化快照与本人、试点报价有效期 5 分钟；重校地址、价格、原时段、上架、活跃 COD 上限后原子落订单、事件、预约配额、库存预占、收款/余额和 outbox；注入日志写失败验证回滚所有变更。订单写入后再调用需引用其 ID 的端口；测试事务内唯一键重试与已提交响应重放。
- [ ] 写时钟测试：即时进入 `PREPARING`；预约初始 `SCHEDULED`，准确到达 `dispatch_at` 后可重跑一次性唤醒、不自动放单；订单因重试延迟而跨窗口仍保留原窗并告警。`jobs.go` 用租约 + 状态条件幂等，扫描补偿漏执行，独立暂停新单不影响存量收尾。`prepare` 写备妥和分拣记录；`dispatch` 一次创建真实任务。
- [ ] 在 `cancel.go` 实现用户、运营取消与库存处理。测试截止时刻和备货/放单竞争、取消与取货竞争、上游失败、已分拣两阶段归架。取消事务关闭未完成任务、调用资金撤销/退回、仅对符合条件的窗口释放容量；未分拣马上释放库存，已分拣留 `RESTOCK_PENDING` 直到验收归架；损坏的预占单位在归架命令中释放预占并同事务减实存记损耗。已取货订单不走取消，异常进入退回流程；验收入库只加实际可售退回量。
- [ ] 在 `dispatch.go`、`delivery.go` 实现抢单、回收、取货、送达/退回。用同步屏障测两骑手抢一单、同一骑手抢两单、回收/取货冲突；命令校验站点、启用、任务归属和前序，已分配骑手暂时下线可完成原任务。取货消费预占；送达对 COD 要求实际全款确认，并与 COD 收款、状态、日志、收入同提交；余额正常送达不再扣款。拒付/少付不确认收款，不允许 `DELIVERED`，退回验收后进入 `RETURNED`，不产生默认收入。运维复核关闭 COD 活跃守卫的终态。
- [ ] 安全交叉测试：大厅不泄露房间/手机号，已指派骑手仅履约期可读本人联系信息；历史对其他骑手及客户不可见；催单按站点和归属限频，消息标记仅限本人；看板用真实事件、COD 已收与余额实付减已退款，不用应收做净收。 `rider.go` 可查询本人收入，不做提现。
- [ ] 由 P05 提供退款编排：交接前走取消；未送达退回由运营验收，在同事务调用 `FinalizeReturnSettlement` 退原余额或取消 COD 应收，失败不推进 `RETURNED`；仅已送达方走人工售后退款，审批/线下兑付锁定订单后调用结算端口，不允许批准人自审。G2 重放空库迁移并运行 P01–P05 联合测试，开放 P06 实联调而非提前部署。

**命令：** 在 `backend/` 执行 `go test ./internal/fulfillment/...`、`go test -tags=integration ./test/integration/...`、`go test -race ./...`。**证据：** `TRADE-01/02/03/04`、`SLOT-02/03`、`PAY-01/02/03`、`RIDER-01/02`；逐项记录哪次事务赢、最终库存、时段计数、账本、收款、收入和状态。
