# P07 事故响应与告警演练

日期：2026-11-19，Asia/Shanghai。以下为获准隔离预发的操作规程，正式 OPS-01/02 演练 **NOT RUN**，G4 **BLOCKED**。没有姓名、接收通道及实际送达回执不能判告警通过。先填写 [证据模板](evidence/README.md)，不要把日志出现当作到人告警。

## 1. 当前可观测能力与告警阻塞

实际 Go 输出 JSON 到stdout/journald：`startup_failed`、`http_request`（request_id、status，无路径/耗时）、`order_jobs_retry`（无原因）、`order_operational_alert`（event_id、kind、station_id、order_id、recipient_ids）。订单告警 `event_id=fulfillment-outbox:<id>`，本机只缓存最近1024个去重键；重启后可重发。worker租约30秒、每秒扫描、最多100项。SQL事务提交后才置finished_at；日志Sink成功即可完成任务，**没有外部短信/IM/邮件/寻呼及送达确认**。日志丢失后不能假设outbox自动重发已finished事件。

正式方案需SRE部署独立于API的日志采集/relay：持久游标采集journald → 独立持久缓冲 → 以event_id去重并映射station/recipient_ids到经批准值班表 → 批准通道通知 → 保存平台消息ID、接收人及送达/确认时间；失败指数退避、重试上限触发备用通道与二线，定时端到端合成心跳。relay凭据仅放密钥系统，不能写Caddy/API环境示例。relay须对已采集未确认消息断点续传；采集器故障、磁盘满、journal保留不足均需独立探针。此方案是待实施接口，**当前没有实现/资源/实际姓名**，下一责任方SRE/发布负责人（外部通道）与总控/P00/P05（若需可靠业务投递接口）。没有独立可靠采集确认不能宣称业务exactly-once告警。

| 演练 ID / 信号与初始建议阈值 | 一线 → 二线 / 必存证据 | 当前缺口 |
|---|---|---|
| OPS01-GO：进程inactive/本机readyz连续3次失败（10s周期）或5xx≥0.5%持续5min | SRE值班 → 发布/后端；失败探针、unit退出、通知送达时间 | 外部探针/接收人未登记 |

## 2. 通用响应与暂停新单/放单

事故指挥由当班发布负责人担任，SRE保存时间线；运营接管订单，财务核现金/余额，DBA保护数据库，安全保存独立审计。先记候选/制品SHA、环境ID、现有开关/迁移摘要、UTC与Shanghai时间、首个异常与已提交请求区间。禁止删除首错或用复测覆盖日志。

**业务暂停**：由获准配置管理者原子更新 `/etc/campus/api.env` 的 `ORDERS_ENABLED=false` 与 `DISPATCH_ENABLED=false`（文件值不在终端打印），记录配置版本并执行：

```sh
sudo systemctl restart campus-api
sudo systemctl is-active campus-api
curl --fail --silent --show-error http://127.0.0.1:8080/readyz
sudo journalctl -u campus-api --since '<incident-start-ISO>' --output=cat
```

这不是动态开关；无SIGHUP热重载、管理接口或即时全局熔断。重启前已进入事务的请求可能已提交；在途结果不明应先查订单/批次结果，再同一Idempotency-Key同体重试，不能换键重下。短暂停机按批准窗口告知运营。`BALANCE_ENABLED=false` 可停止新余额支付但不冻结历史退款；不要关库或撤app DML权限来模拟业务暂停，否则存量也无法收尾。

同一候选/环境用合成既有单逐项验证：新报价/新下单被拒、prepare后dispatch被拒；原单查询、合法取消、运营归架、退回验收、COD实际已收款退款审批与记录实际线下退款、独立财务制单/复点仍可；已有合法任务取送/退回按业务规则运行。worker继续处理预约/逾期并不自动放单，不得伪造送达或现金。保存请求状态、审计行与前后只读对账，不在文档预填“PASS”。

**数据停写**不同于业务暂停：PITR或资金不一致无法安全继续时，按recovery停止API/worker及导入/迁移/其他写入者，网关隔离写流量，DBA确认无写连接；全停写期间存量命令也暂停，由运营保留待处理清单，恢复核对后再通过API收尾。

恢复新业务需SRE/DBA证明故障解除、运营/财务核存量/差额、指挥人批准；先保持两开关false恢复服务，核对后改为获准值并再次重启；观察至少15分钟且告警到人/队列回落/不变量成立才结束事故。

## 3. 分故障演练步骤

每个故障只注入获准目标，保留故障前、注入、检测、送达、确认、处置、恢复、对账八个时间点。演练窗、回退方式、影响范围由发布负责人预批，未授权不故障注入。

| 场景 | 可执行流程 / 恢复证明 |
|---|---|
| Go进程退出 | 在隔离目标按批准方式停止/终止本unit，保存退出状态及Restart策略效果；从旁路探针看到失败并收到真实通知。启动固定版本，核ready与存量流程。正常systemctl stop不会因Restart=on-failure自动恢复，不以此推断策略无效 |
| PG失联/恢复 | DBA仅对隔离应用连接施加批准的网络拒绝或停止隔离PG；验证ready失败、业务无假成功、SRE/DBA收到通知。撤故障后核PG恢复日志、提交不明区间的幂等结果和所有不变量；不得直接重试不同键扣款 |
| worker/outbox滞后 | API与worker共进程，当前没有单独worker开关。只在批准测试环境暂时停止该unit或对指定测试事务制造可回退锁等待，记录方法/锁ID/超时；独立监控必须仍工作。恢复后等待30秒租约到期再观察重复运行；不手改lease/finished/attempts；同业务键只一条状态/收入/退款 |
| 预约过期 | 用预发批准的短窗口/固定测试数据等待到dispatch_at与ends_at；核一次SCHEDULE_WOKE及OVERDUE，运营实际收到提醒并确认。逾期订单由运营决定合法取消、联系或继续履约；不自动换窗/送达，开关关闭期间不放单 |
| COD非零差额 | 财务甲对真实合成收款制单，财务乙录入经批准的测试少缴/多缴，核DISCREPANCY与difference_fen=expected-actual（正为少缴、负为多缴）；通知财务主管/运营。保存受限现金交接凭据；一人不得制单复点。原复点不可改删，不伪造第二次复点冲销；后续追补/差额结案尚无应用接口，交P04/财务批准的线下异常账并保留关联 |
| 余额核对失败 | 不在业务库直接改钱包造错。隔离故障副本可使用受批破坏夹具/模拟只读对账输出触发通知；区分“通知链路测试”和“真实数据恢复”。发现真实差异，关新单/余额并保留账本，停止导入，财务+P04逐笔核查、按恢复/前向修复方案审批；不手改金额或删重复流水 |
| OTP/IdP不可用 | main接线前标BLOCKED；接线后在隔离供应商沙箱或受控网络故障中验证登录失败、无降级假身份、无OTP泄露，通知P01和运营。恢复后真实OTP一次性/限频及员工近期MFA复测，保留现有合法会话的正常权限约束 |

非零COD差额的浏览器分支未被P06本机矩阵覆盖，需总控/P06/P08另跑，不能仅凭SQL或已有零差额PASS代签PAY-02。完整账本导出/批次GET未提供时，DBA用 [reconciliation.sql](reconciliation.sql) 的受限只读结果支持财务；它不能代表应用权限或UI可用。

## 4. 回切与首错诊断

固定版本升级/回切按deploy手册；旧版必须已在前向兼容数据上验证。禁止重跑旧迁移器、反迁移和业务在线手改状态。恢复后须核本次可能提交的订单、库存、时段、收款、退款、收入、outbox，核对失败不恢复新单。

以下两起首错独立跟踪；复测和新环境未重现不能关闭根因：

| 诊断ID | 永久首错与当前状态 | 下一证据与责任 |
|---|---|---|
| P05-PG-CRASH | `p05-frozen-races-ten-02` FAIL；2026-11-19 01:11:00–01:11:03 CST postgres.exe 0xC0000005，020_001 CREATE TABLE products期间，01:13:04恢复；诊断OPEN、根因UNCONFIRMED | DBA/P07在获准接近预发的独立PG版本/平台保留dump及匹配符号、bin/hash、事件/PG日志时序，完整迁移000–050与有针对性的故障恢复/并发不变量验证；源证据在.p05目录 |
| P06-NODE-CRASH | 首次回放Node测试子进程0xC0000005，首错FAIL；当次PG未崩，同源码独立复测16/16；诊断OPEN、根因UNCONFIRMED | P06/CI运行者记录Node/浏览器/OS二进制版本摘要、子进程dump与测试日志；PG日志独立关联；不得归并成P05事故 |

P05历史Go race因缺gcc为NOT RUN，必须由具备CGO=1和C编译器的真实CI补证，不能用屏障测试替代。若本轮再现崩溃、持久数据不一致或确认产品缺陷，立即交总控重开受影响门禁，停新单并保护证据；无证据不能宣称“只是环境问题”。

审计副本由独立导出者读取audit_events必要字段，签摘要转存；运行角色只能追加，不能修改删除。数据库内append-only触发器不等于独立受限审计存储已存在。跨包未交付的导出/采集/relay列BLOCKED，不用普通日志文件替代。

机制参考：[systemd Restart](https://www.freedesktop.org/software/systemd/man/latest/systemd.service.html#Restart=)；具体行为以本候选unit和实际安装版本验证为准。
