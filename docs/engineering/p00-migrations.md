# P00 迁移编号冻结表

版本格式为 `NNN_NNN_name.sql`，数据库中的版本为前两个数字段（如 `020_001`），全库唯一。迁移只新增；已应用文件的名称与 SHA-256 必须与构建清单一致。迁移历史必须是构建清单的有序前缀，新增迁移与历史登记在同一事务提交。

| 编号段 | 所有者 | 基线内容及边界 |
| --- | --- | --- |
| `000_*` | P00 总控 | `000_001_base.sql`：stations、idempotency_keys、audit_events、outbox_jobs；schema_migrations 由迁移器维护 |
| `010_*` | P01 | 身份、会话、地址、角色绑定 |
| `020_*` | P02 | 商品、规格、库存及库存流水 |
| `030_*` | P03 | 时段及容量预占 |
| `040_*` | P04 | 收款、余额账本、退款与对账 |
| `050_*` | P05 | 报价、订单、履约、任务及跨包外键 |

P00 独立补丁只有 `000_001_base.sql`。P01–P04 必须能在 P00 加本包迁移上独立测试，W1 不引用其他 W1 私有表。总控在 G1/G2 用空库按版本顺序重放，不能把现有开发树中的 010–040 当作 P00 基线。共享 `migrations/embed.go` 和迁移器只由总控修改。

隔离 PostgreSQL 验证：在 backend 运行 `go test -count=1 -tags=integration ./internal/platform/...`。显式设置专用 `TEST_DATABASE_URL`；未设置必须失败，不允许降级为 SQLite、默认库或生产连接。生产迁移账号与应用账号分离，应用不运行迁移。
