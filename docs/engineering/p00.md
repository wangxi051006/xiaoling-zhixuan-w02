# P00 工程基线

以 `docs/superpowers/plans/2026-11-18-backend/01-foundation.md` 为验收源。开发副本不使用 Git；交付补丁不包含 node_modules、原型检查依赖、构建缓存、数据库数据或真实凭证。原型 `index.html`、`demo/`、`styles/` 不改。

## 本地启动

1. 准备隔离 PostgreSQL，测试连接串设为 `TEST_DATABASE_URL`，测试账号需要创建和回收临时 schema/role 的权限。禁止把应用/迁移/生产连接串用作测试连接串。
2. 在 `backend/` 设置 `APP_ENV=development` 和显式 `DATABASE_URL`，运行 `go run ./cmd/api`。默认 `127.0.0.1:8080`；业务路由未实现，只有本机 `/healthz`、`/readyz`。数据不迁移也不会假冒业务已就绪；`/readyz` 在 P00 仅探测数据库连通。
3. 在 `web/` 运行 `npm ci`、`npm run dev`，分别访问 `/user.html`、`/rider.html`、`/admin.html`。开发 API 代理仅允许回环目标；默认 `http://127.0.0.1:8080`。`npm run build` 输出三个 HTML 入口和共享静态资源；它们不包含演示数据和业务实现。

## 数据库与入口约定

在隔离环境验证建表和版本记录：设置 `MIGRATION_DATABASE_URL` 后运行 `go run ./cmd/api migrate`，再次运行应保持同一迁移历史。生产应用账号与迁移账号独立：预创建数据库/schema，迁移账号拥有 schema，执行 `p00-runtime-grants.sql` 模板后，运行账号无 DDL、更改迁移历史或更改审计记录的权限。迁移命令不接受无验证 TLS 的生产连接；生产 API 不执行迁移。在受限数据库诊断中查迁移失败，避免将连接信息、SQL 内容或业务值送到应用日志。

预发用户、骑手和管理端使用各自的 Host，每个 Host 只映射自己的 HTML 和共享 `assets/`，其他端入口和未知路径返回 404。只代理 `/api/v1/`，健康探针由受信本机访问，管理入口需处于受控网关。实际 Caddy 配置、预发域名、升级/回滚与恢复演练由 P07 验收。

## 本地验证命令

- 根目录：`node contracts/generate.mjs --check`。
- `backend/`：`go test ./...`、`go vet ./...`、`go test -tags=integration ./internal/platform/...`。用支持 CGO 的 CI 运行 `go test -race ./...`。
- `web/`：`npm ci`、`npm run typecheck`、`npm test`、`npm run build`、`npm run test:e2e`。E2E 要求已安装 Chromium，或设 `BROWSER_EXECUTABLE` 指向 Chrome/Chromium。
- 启动验证：在 `backend/` 构建 `go build -o <binary> ./cmd/api`，根目录运行 `node tools/api-smoke.mjs <binary>`。它只使用显式隔离 `TEST_DATABASE_URL`，测试后关闭自建 API 进程。

依赖版本以 `go.mod`、`go.sum` 和 `package-lock.json` 为准。包级工作继续使用独立 schema 或独立测试实例、明确写域和迁移编号；无 Git 时只在开发副本中串行进行。

迁移编号冻结表见 `p00-migrations.md`；合成契约样本在 `contracts/samples.json`；本次 G0 清单、命令结果、补丁应用方法及开放项见 `p00-recheck.md`。独立 P00 基线与含 W1 成果的开发目录应分别验证，不用后者替代空骨架的可复现性。
