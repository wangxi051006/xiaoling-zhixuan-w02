## 实现范围

- `backend/internal/fulfillment/` 实现冻结的 27 条客户、运营和骑手路由，使用真实身份、商品、时段和结算端口。报价绑定本人、规范化商品行、地址/价格/原时段快照及五分钟有效期；新单幂等、活跃 COD 守卫、库存、容量、结算、事件、审计和 outbox 具有一致事务边界。
- 实现预约唤醒、租约恢复与扫描补偿、备妥/放单、用户与运营取消、分拣后归架及损耗、抢单/回收/取货/送达/退回/验收、实际 COD 收款和唯一收入、原钱包退回以及已送达人工售后退款编排。存量收尾不受新单和放单暂停阻断。
- 大厅与历史使用脱敏 DTO；当前骑手履约期内才可读取联系方式。骑手命令的幂等缓存不保存联系方式，重放在当前订单锁和归属下重新生成允许读取的投影。
- 下单按 UTC 分钟限制每账号 10 次、每来源 30 次尝试；仅使用连接的 RemoteAddr，不信任客户端转发头，持久化来源摘要。限频使用订单事务之前的独立短事务，失败订单和取消不退回预算，已提交幂等重放不再次计数。固定窗是试点阈值，生产代理来源策略须在 P07 校验。
- 催单与逾期告警由同进程 worker 实际消费。当前启用的指派骑手通过本人消息读取接收催单，暂时下线仍可接收原任务催单；档案停用、无指派、未放单及逾期事件路由到本站启用运营账号。单个失败任务保留租约重试，同批独立任务继续推进，避免提醒故障阻塞预约。实际 main 注入结构化日志接收器，只输出稳定事件 ID、类型、站点、订单和接收者标识。发送失败可重试，进程内最近 1024 个成功 ID 去重；跨重启或缓存淘汰后仍是携带同一 ID 的至少一次投递，外部需按 ID 去重。真实告警到人配置仍归 P07。
- 新增 `050_001_fulfillment.sql`，保留真实跨域外键和只追加事件/收入约束。订单时段 FK 延迟至提交时检查，避免插入订单获得 KEY SHARE 后再进入时段 FOR UPDATE 的锁升级死锁；没有删除外键。
